# OPA 实现说明（Audsley 语义修复版）

## 1. 标准 Audsley 语义

在每一轮分配当前最低优先级时，OPA 只需要回答一个问题：

- 某个候选任务作为“当前最低优先级任务”时，它自己是否可调度？

若可调度，就固定该候选任务到这一层，然后在剩余任务集合上继续下一轮。

## 2. 本项目修复前后的差异

修复前（错误）：

- 先把候选任务放到当前最低优先级；
- 再对整个 `trial_order` 做完整任务集可调度性测试；
- 用“整序是否可调度”代替“候选任务是否可作为当前最低优先级”。

修复后（正确）：

- OPA 阶段使用 candidate-level 测试；
- 仅检查候选最低优先级任务在当前干扰集合下是否可调度；
- 最终排序确定后，再使用完整 method 测试进行整任务集验证。

## 3. 实现分层

- `amc_py/priorities.py`：实现 Audsley 逐层分配框架与候选任务判定入口。
- `amc_py/experiments.py`：
  - 为 `smc / smc_no / amc_rtb / amc_max` 映射对应的“最低优先级候选任务判定函数”；
  - OPA 成功后再调用完整 `method_fn(ordered_tasks)` 得到最终可调度性结论。

这保证了：

- OPA 的判定语义不再被“整序过早失败”污染；
- OPA 与最终分析使用同一方法口径（SMC 用 SMC，AMC-rtb 用 AMC-rtb，等）。

## 4. 测试覆盖

`tests/test_opa.py` 覆盖了以下关键点：

1. OPA 返回完整优先级映射；
2. 候选语义与整序语义可区分（回归用例）；
3. OPA 成功后，用同一 method 的整序测试复验通过；
4. 输入顺序变化下，OPA 结论保持一致。
